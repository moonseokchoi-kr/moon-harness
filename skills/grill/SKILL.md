# grill — frontier 라운드 인터뷰

사용자와 공유된 이해에 도달할 때까지 계획·결정·요구사항을 캐묻는다. 모든 결정은 그 아래 결정들을 매달고 있는 **설계 트리**다. 추측으로 빈칸을 메우지 않고, 사용자가 말하지 않은 것을 조용히 가정하지 않는다.

## 사용 조건

- **대화형 세션에서만** 시작한다. `/loop`, 스케줄, CI 같은 비대화형 실행에서는 grill을 시작하지 않고 "사용자 입력이 필요하다"고 보고한 뒤 멈춘다.
- `/grill`로 단독 호출할 수 있다. 호출한 쪽의 진행 상태는 다루지 않는다.

## 라운드 진행

**frontier** = 선행 결정이 모두 확정되어 추측 없이 지금 물을 수 있는 질문 집합.

1. frontier 전체를 한 라운드에 모아 묻는다. 한 번에 한 질문씩 묻지 않는다.
2. 질문마다 번호와 **추천 답**을 붙인다. "네"가 추천 답 수락이 되도록 문장을 쓴다.
3. 아직 열린 다른 질문에 의존하는 질문은 이번 라운드에 넣지 않고 다음 라운드로 미룬다.
4. 사용자가 답하면 확정된 결정으로 트리를 갱신하고 frontier를 다시 계산해 다음 라운드를 묻는다.

라운드 형식:

```
Q1. <질문 제목>: <질문 본문, 선택지 포함 가능>
→ 추천 답: <추천>

Q2. <질문 제목>: <질문 본문>
→ 추천 답: <추천>
```

## 사실은 직접 조사한다

환경(코드, 파일, 도구, 이력)에서 알 수 있는 사실은 사용자에게 묻지 않고 직접 조사한다. 사용자에게는 **결정**만 묻는다.

- 조사는 서브에이전트(`subagent_type: Explore`)로 보낸다. sdd 안에서는 why / code-mapper를 이렇게 보낸다.
- 조사를 기다리느라 라운드를 막지 않는다. 조사 결과에 의존하는 질문만 미루고 나머지 frontier는 지금 묻는다.

## 종료 조건

질문을 끝낼 시점: 다음에 물을 질문 3개를 적었을 때 각각 사용자 답을 추천 답 그대로 예측할 수 있으면 종료한다. 예측할 수 없는 질문이 하나라도 있으면 그 질문부터 라운드로 묻는다.

## 요약과 명시적 yes

종료하면 5~8줄 요약을 제시한다. 요약에는 반드시 **하지 않을 것**(이번 범위에서 제외하는 것)을 포함하고, 명시적 yes를 요구한다.

- "네" 또는 "yes"만 승인으로 인정한다.
- "좋아 보여", "ok", "진행" 같은 암묵적 동의는 승인으로 취급하지 않는다. 요약을 수정하거나 yes를 다시 요청한다.
- 승인 전에는 요약을 근거로 구현·문서화 같은 후속 작업을 시작하지 않는다.
