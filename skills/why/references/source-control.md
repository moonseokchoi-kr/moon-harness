# 소스 컨트롤 조사 요령

소스 컨트롤은 항상 쓸 수 있는 유일한 근거 카테고리다. 읽기 명령만 쓴다.

## 명령

- `git blame -L <시작>,<끝> <파일>`: 줄 단위 마지막 수정 커밋. 포맷만 바뀐 커밋이면 `-w -M -C`로 공백·이동을 무시하고 다시 본다.
- `git log --follow -p -- <파일>`: 이름 변경을 넘어선 전체 이력과 패치.
- `git log -S'<문자열>' --oneline -- <경로>`: 특정 문자열(임계값, 플래그 이름)이 처음 들어온 커밋 찾기.
- `git log -1 --format=%B <커밋>`: 커밋 본문에서 PR 번호 `(#1234)`와 티켓 ID 추출.
- `gh pr view <번호> --json title,body,author,createdAt,mergedAt,labels,closingIssuesReferences,comments,reviews`: PR 설명과 리뷰 토론.

## 읽는 법

- PR 본문과 리뷰 코멘트가 구현 당시 근거가 가장 자주 남는 곳이다.
- 커밋 메시지가 "fix", "cleanup" 수준이면 그것만으로 근거라고 하지 않는다. 추론으로 분류한다.
- 같은 시기·같은 작성자의 인접 커밋과 함께 추가된 테스트는 동기의 간접 증거다.
- 마지막 수정 커밋이 리팩터링·포맷이면 그 이전 커밋까지 거슬러 올라간다.
