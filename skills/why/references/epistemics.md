# 사실 / 추론 / 모름

코드의 이유는 단편적이고 때로는 서로 모순된 기록에만 남는다. 확신을 부풀리지 않고 구분해서 전달한다.

## 구분

- **사실**: 작성자가 실제로 쓴 문장이 답한다. PR 본문, 티켓, 코드 주석, 설계 문서, 작성자 본인의 채팅 메시지. 표현은 단정형 + 인용: "이 가드는 X 때문에 있다 (PR #123 본문)".
- **추론**: 정황 여러 개가 같은 결론을 가리키지만 직접 서술은 없다. 근거 사슬을 보인다: "A와 B로 보아 C일 가능성이 높다. 근거: ...".
- **모름**: 찾아봤지만 확인하지 못했다. 무엇을 어디서 어떤 키워드로 찾았는지 적는다. "찾지 못했다"보다 "이슈 트래커를 키워드 A, B로 검색하고 이 파일을 건드린 PR 6건을 확인했으나 근거 없음"이 쓸모 있다.

## 규칙

- 코드가 X를 하니 작성자가 X를 원했을 것이라는 문장은 사실이 아니라 추론이다.
- 모순되는 출처는 하나를 고르지 말고 둘 다 적는다. 가설이 여럿이면 각각 어떤 증거가 있는지 나눠 쓴다.
- 오래된 기록은 현재 코드와 어긋날 수 있다. 날짜를 같이 적는다.
- 모름은 정상적인 결과다. 메우려고 추측하지 않는다.
- 변경 제약(Preserve/Change/Avoid/Risk)에서 사실은 Preserve/Avoid 근거로, 모름은 Risk로 옮긴다.
