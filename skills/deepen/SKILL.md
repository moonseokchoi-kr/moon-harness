# deepen — 더 깊은 버전으로 다시 쓰기

작업을 크게 만들지 않고 깊게 만든다. 출처: Felix Rieseberg, "How to be more ambitious: A tutorial for humans with models" (2026-10-13)의 Depth 절 메타 프롬프트를 이 하네스 형식으로 옮긴 것.

`deepen`은 **넓히는** 단계이고 `grill`은 **쳐내고 확정하는** 단계다. deepen 결과를 그대로 실행하지 않는다.

## 사용 조건

- 대화형 세션에서만 쓴다.
- 작업이 한 줄짜리 수정이거나 이미 spec이 확정된 상태면 쓰지 않는다. 깊게 만들 여지가 없다.

## 절차

### Step 1 — 작업 확정

사용자가 준 작업을 한 줄로 다시 적는다. 모호하면 가장 그럴듯한 해석을 밝히고 진행한다.

### Step 2 — 네 가지를 짚는다

1. **전문가가 더 할 일**: 이 분야 최고 전문가라면 사용자가 요청하지 않았지만 할 일.
2. **원천 자료**: 이미 가공·요약된 자료 대신 전문가가 출발점으로 삼을 가장 원천에 가까운 자료 (로그, 원본 데이터, 코드, 커밋 이력, 크래시 덤프 등).
3. **방법·도구**: 전문가가 쓸 구체적인 방법과 도구. "전문가처럼 분석" 같은 어휘 교체가 아니라 실제 도구 이름을 적는다 (DB 쿼리, 통계 모델, 프로파일러, 재현 스크립트 등).
4. **외부 검증**: 사용자도 모델도 아닌 무엇이 결과가 맞다고 보여줄 수 있는가. 테스트, 빌드, 벤치마크, 실측, 백테스트처럼 실행 가능한 신호를 우선한다. 모델의 자기 평가는 검증으로 인정하지 않는다.

2번과 3번은 환경에서 확인할 수 있으면 직접 조사한다. 존재하지 않는 자료나 도구를 가정하지 않는다. 확인하지 못한 것은 "미확인"으로 표시한다.

### Step 3 — 프롬프트 재작성

네 가지를 반영해 작업 프롬프트를 다시 쓴다.

- 범위를 늘리지 말고 깊이를 늘린다. 새 기능·새 산출물을 덧붙이지 않는다.
- 외부 검증 수단을 완료 조건으로 프롬프트에 넣는다.

## 출력 형식

```
작업: <한 줄>

1. 전문가가 더 할 일: ...
2. 원천 자료: ... (확인됨 / 미확인)
3. 방법·도구: ...
4. 외부 검증: ...

재작성한 프롬프트:
<프롬프트>

다음 단계: 범위를 쳐내고 확정하려면 `/grill`
```

결과는 대화로만 보고한다. 파일로 저장하지 않는다.
