## 판정 함수 / fail-safe 규약

### 결합 verdict 필드 (fail-safe `ok` 재정의 시에만)

어떤 규약이 `ok`를 "판정 자체가 기술적으로 성공했는가"로 **재정의**해 `ok=True`와 위험 상태
(`dirty`/`diverged` 등)가 공존할 수 있게 만들었다면, 그 판정 함수의 반환 dict는 호출자가 그대로
분기할 수 있는 결합 필드(예: `precondition_failed = not ok or dirty or diverged`)를 **반드시**
포함한다. 결합 필드는 구성 필드와 **동일한 return 문에서 계산**한다(나중에 대입/변경 금지 —
구성 필드와 어긋날 수 있다). docstring 경고만으로는 방어하지 않는다. `ok`가 통상 의미
(성공/실패)인 함수에는 적용하지 않는다.

- 근거: `.harness/LEARNING.md` `## 2026-07-30 — kompound-snapshot-hook / T-5-git-state`
- critic: NARROW (원안 "모든 판정 함수는 결합 필드를 노출한다"는 과확장 — 통상 `ok`에도 불필요한
  중복 불리언을 강제하고, 별도 대입된 결합 필드는 구성 필드와 drift하는 2차 진실원이 된다)
- 실제 적용 예: `hooks/lib/kompound_snapshot/git_state.py` `precondition_failed`

## 결정적 산출물 이름 / 게이트 설계

### 결정적 네이밍 도입 시 기존 산출물 이름 정합 감사

기존에 손으로 만들어진 산출물 코퍼스 위에 결정적 네이밍/ID 생성 규칙을 도입하는 사이클은,
게이트를 켜기 **전에** spec의 태스크로 "기존 코퍼스 전수 대조"를 넣고 **결과를 수치로 기록**한다

정본 결정 없이 게이트만 붙이면 "정확히 막지만 재시도로는 뚫리지 않는" 교착이 된다.

### 비수렴 상태는 사람 결정으로 승격

게이트가 올바르게 차단했으나 **입력이 그대로인 채 재시도해도 영구히 같은 결과가 나오는** 상태는
retry 카운터를 올리지 말고 `human_decision_required`로 승격 보고한다. 사람 메시지에
"다음 실행에서 재시도합니다" 류의 수렴 가능성을 시사하는 문구를 쓰지 않고, **무엇을 사람이
결정해야 하는가**를 적는다. 재시도로 수렴 가능한 상태(일시적 오류, 외부 의존 실패)와는 코드
경로를 분리한다.

- 근거: 동일 엔트리
- critic: **UPHELD** — 라이브 확인. `hooks/lib/kompound_snapshot/report.py:300-311`이 카탈로그 단계
  **모든** 실패에 "다음 실행에서 재시도합니다"를 반환하며, 그중 `bidirectional_count` 실패는
  결정적으로 비수렴이다(raw는 이미 커밋됐고 다음 실행이 동일 이름을 재생성). 즉 도달 가능한
  상태에서 메시지가 **적극적으로 거짓**이다.
- 후속: `report.py` 메시지 분기는 하네스 티어 — `harness-proposals/`에 별도 항목으로 올림.

## 문서에 적는 실행 명령

### 인터프리터·툴 경로를 적지 말고 확정 절차를 적는다

SSOT 문서(`CLAUDE.md`/`CLAUDE.local.md`)와 SDD 산출물(spec/arch/task)에 **읽는 쪽이 그대로
복사해 실행할 명령**을 적을 때, 인터프리터/툴의 절대경로나 `PATH=...` prefix를 적지 않는다.
자리표시자(`<PY>` 등) + **확정 절차**(어떤 명령을 실행해 실제로 그 도구를 가진 인터프리터를
판별하는가)를 적고, 명령은 `<PY> -m ...` 형태로 고정한다.

이유는 "경로가 틀렸다"가 아니라 **잠복성**이다. 존재하지 않는 경로의 prefix는 무해한 no-op이라
오류가 드러나지 않는다. 패키지 매니저가 그 경로를 만드는 순간 정상 동작하던 인터프리터를 가려서
깨지고, 발현 시점이 어떤 코드 변경과도 무관해 원인 추적이 어렵다.

적용 범위는 **문서의 복사-실행 명령**이다. 재현성을 위해 경로를 고정하는 것이 목적인 곳
(CI 러너 핀, 컨테이너 이미지, lockfile, shebang)에는 적용하지 않는다. 이미 완료된 사이클의
산출물 문서는 재실행 대상이 아니므로 소급 수정하지 않는다.

- 근거: `.harness/LEARNING.md` `## 2026-08-06 — harness-docs / 인터프리터 경로 하드코딩이 무해→유해로 전환`
- critic: NARROW (원안은 CI/컨테이너/shebang의 정당한 경로 고정까지 금지로 읽혀 범위를
  "복사-실행 명령"으로 한정. 이 머신의 pytest 실측 사례는 `CLAUDE.md` 빌드/테스트 절에 이미
  있으므로 재기술하지 않고 일반 원칙만 승격)
- 실측: 3번째 독립 발현. 선행 2건은
  `docs/sdd/design/arch/2026-06-30-cross-project-learning-aggregation.md:299`, `HANDOFF.md:74`
  (둘 다 실행자가 우회하고 SSOT는 고치지 않음). 현재도 미수정 산출물 20여 개 파일에 잔존.

## 공유 worktree git

### 병렬 커밋은 경로 지정 커밋으로

공유 worktree에서 병렬 에이전트가 커밋할 때는 `git add <소유 파일>` 후
`git commit -m "<msg>" -- <소유 파일 경로들>`로 한다. `git commit`은 인덱스 전체를
커밋하므로, 소유 파일만 add해도 다른 에이전트가 먼저 stage한 파일이 내 커밋에 섞인다.
경로 지정 커밋(`--only` 기본 동작)은 지정 경로만 커밋하고 다른 stage분은 인덱스에 남긴다.

- pathspec은 **파일 경로**로 나열한다. 디렉터리를 주면 그 아래 남의 stage분까지 커밋된다.
- 새 파일은 먼저 `git add`해야 한다(안 하면 pathspec 에러로 실패 — 정상).
- `git mv`는 **옛 경로와 새 경로를 둘 다** 지정한다. 새 경로만 주면 옛 경로 삭제가
  인덱스에 남아 다음 에이전트 커밋에 흡수된다.
- 경로 지정 커밋은 stage 내용이 아니라 working tree 내용을 커밋한다(`git add -p` 부분 stage 무시).
- merge 진행 중에는 쓸 수 없다(partial commit 거부) — 병렬 워커는 merge하지 않는다.

- 근거: `.harness/LEARNING.md` `## 2026-10-19 — sdd-phase1-code-context / 공유 worktree 커밋에 타 태스크 stage 흡수`
  (보완 대상: `## 2026-06-17 — self-improving-harness / Phase 4 orchestration`)
- critic: NARROW (원안은 rename 시 옛 경로 삭제가 인덱스에 남아 동일 사고 재발 — 양 경로 지정 조건 추가.
  디렉터리 pathspec·부분 stage 함정 명시. 스크래치 repo 실측)

## 스킬·에이전트 Markdown 정적 테스트

### 핵심 행동 문장은 절/줄 범위로 고정한다

스킬·에이전트·템플릿 Markdown의 **핵심 행동 문장**(에이전트가 반드시 따라야 하는 지시)을
검증하는 정적 테스트는 "키워드가 파일 어딘가에 있는가"로 단언하지 않는다. 해당 `##` 절을
잘라낸 범위(절 헬퍼) 안에서 찾거나, 한 줄에 여러 정규식이 동시에 맞는지(줄 헬퍼)로 고정한다.
파일 전체 검색은 frontmatter·다른 절의 같은 단어로 통과해, 핵심 문장을 지워도 GREEN이 된다.
금지어 전수 스캔처럼 "어디에도 없어야 한다"는 단언은 파일 전체 범위가 맞으므로 적용하지 않는다.

### 한국어 문서에서 식별자 경계는 ASCII lookaround로

한국어 본문 안의 ASCII 식별자(에이전트명, 라벨 등)를 경계 매칭할 때 `\b`나 `(?![\w-])`를
쓰지 않는다. Python `re`의 기본(유니코드) 모드는 한글을 `\w`로 취급해 `ui-designer가`,
`SIMPLE이면`에서 경계가 성립하지 않는다(매칭 실패 → 금지어 스캔이면 거짓 GREEN).
`(?<![A-Za-z0-9_-])NAME(?![A-Za-z0-9_-])` 음성 lookaround 또는 `re.ASCII` 플래그를 쓰고,
"이름+조사" 케이스를 테스트 자체의 단위 테스트로 둔다.

### 처음부터 통과한 문서 테스트는 삭제 변이로 1회 확인한다

산문 문장을 단언하는 정적 테스트가 **정당한 RED(그 문장 부재로 인한 실패)를 거치지 않고**
처음부터 통과했다면, 대상 파일에서 그 문장만 지운 임시 사본(또는 미커밋 수정)으로 FAIL을
1회 확인하고 되돌린다. 확인 결과(변이 / FAIL 여부)를 태스크 보고에 한 줄 남긴다.
RED를 정상적으로 본 테스트와 코드 대상 테스트에는 적용하지 않는다.

- 근거: `.harness/LEARNING.md` `## 2026-10-19 — sdd-phase1-code-context / 정적 문서 테스트의 거짓 GREEN 두 유형`
  (연관: `## 2026-07-30 — kompound-snapshot-hook / T-10-apply`, 실행 안 된 채 GREEN)
- critic: NARROW (② "ASCII 클래스"는 소비형 클래스로 오구현될 여지 → lookaround/`re.ASCII`로 명시.
